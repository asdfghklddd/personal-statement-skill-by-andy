# 写作工作台

## 素材表

在工作笔记建立这些列，不必把整个表交给用户。

| 经历 | 问题/背景 | 本人动作与边界 | 选择理由 | 结果与证据 | 局限/认识变化 | 目标相关性 | 待确认 |
|---|---|---|---|---|---|---|---|

涉及论文、媒体、讲座、政策数字或行业趋势时，在待确认栏另记来源、作者/观点归属、日期、定义、分母或样本范围；把“来源说了什么”和“申请人如何判断”分开。数字和因果句若没有这些信息，不直接写成强结论。

分清三种贡献：完成了哪些工作；对团队结果有何可支持的贡献；对问题有何新认识。没有论文或奖项也可写课程项目、实习中的判断、自主作品、服务实践；不能把工程实现自动包装成科研突破。

## 渐进访谈

从现有材料挑最缺的两三题，不一次倾倒完整问卷。

**找到问题与动机**
- 哪件事让你发现自己原来的理解不够？当时具体发生了什么？
- 你后来采取了什么行动？如果没有立即行动，现在的兴趣怎样逐步形成？
- 你想继续处理的是哪一个问题，而不仅是哪个行业或职位？

**找到个人贡献**
- 团队如何分工？你独立负责、协作完成、仅旁观的部分分别是什么？
- 当时有哪些可选方案，你选择这一种的依据是什么？
- 最难的步骤是什么？你实际做过什么修改，结果如何？

**找到证据和反思**
- 有什么产物、反馈、观察或评估支持你的判断？数字的时间、基线和样本是什么？
- 哪一项结果未达到预期？你知道是方法限制、数据限制还是暂时无法判断？
- 这段经历以后，你对问题、方法或职业选择有何具体变化？

**找到项目需要**
- 你已有哪些准备，仍不能完成的工作是什么？
- 哪个项目资源与你的下一步有实际联系？你会怎样使用？
- 如果没有这个项目，你的替代路径是什么？为什么仍选择继续学习？不要据此声称只有该校能解决问题。

**找到声音与目标**
- 用你平常说话的方式解释：为什么现在申请？
- 哪句草稿你不会在面试时自然说出来，或者无法解释？
- 毕业后想先做什么？哪些方向已经确定，哪些仍在探索？

## 选材与预算

用“强/中/弱”比较相关性、本人参与、证据和反思，不制造录取分数。优先一段能深入解释的工作，辅以有不同作用的经历。删除重复证明同一能力的素材。缺少实习不必补假实习；缺少论文不必把阅读笔记改叫研究成果。

按题目为每项回答留足篇幅。无分题的研究生 PS 可先把大部分空间分给关键经历与匹配，再以较短开头和结尾连接；这只是起稿策略，不是固定比例。500 词稿通常无法充分解释四五个项目，优先减少项目数。

压缩顺序：重复结论、泛泛赞校、背景常识、无关项目、重复课程、冗长术语。保住个人角色、核心判断、结果口径、项目对应关系及官方必答项。

## 段落微结构

用下面的动作检查段落，不把它们当固定段数或固定字数：

- **开头**：在前一段或第一段尽早出现问题、选择或转向，并让读者知道申请方向。事件只是入口，后面必须有申请人的问题或行动。
- **证据句**：背景 → 本人角色 → 关键动作/选择 → 结果或产物 → 结果边界。工具名只在解释选择时出现。
- **so-what 句**：写判断如何改变、仍缺什么，少写“提升了能力”。一个经历只支持它真正支持的结论。
- **匹配句**：已有问题/缺口 → 核实的课程、方法、实验室或教学方式 → 计划如何使用。来源来自用户提供的当前页面或当期官方材料；不暗示已与导师建立关系。
- **结尾**：回到开头的问题，落在项目完成后可验证的下一步或训练产出。职业方向未确定时，写探索范围和判断标准，不编造职位确定性。

## 按文书类型选骨架

题目有分题时按题目顺序。无分题时可用以下内部骨架，再按学位和项目调整：

| 类型 | 主要推进 | 需要避免 |
|---|---|---|
| Personal Statement | 转向/问题 → 形成的判断 → 后续行动 → 当前选择与下一步 | 自传、苦难目录、把 SOP 的课程清单搬进来 |
| 授课型硕士 SOP | 专业问题 → 准备与项目证据 → 学习缺口 → 课程/实践匹配 → 近期方向 | 把课程写成论文提案或只写学校声誉 |
| 研究型硕士/博士 SOP | 有边界的问题 → 方法接触与结果 → 仍未回答的限制 → 研究组/导师/训练模式 → 范围 | 把宏大领域当问题、虚构方法或导师关系 |
| 单独 Research Statement | 问题与空白 → 材料/方法 → 可行性与限制 → 预期贡献 | 用动机和个人经历填满研究计划 |
| Combined prompt | 短的个人背景框架 → SOP 或研究骨架 | 平分篇幅，写成两篇互不相连的短文 |

## 交付优先

- 写、改、润色和未限定范围的审查，默认返回完整正文；诊断先服务于修订，而不是替代修订。
- 只有用户明确说“只诊断/只打分”时才不交全文。事实缺口写成 `[待确认：...]`，不要因为等待访谈而停工。
- 多校适配时保留事实账本，重写问题、素材顺序、资源用途和结尾；不要只搜索替换学校名称。

## 原创教学示例

下面均为假设练习，不是申请人的事实，不得直接使用。

原素材：团队做了预约工具；本人观察到使用者反复确认预约是否成功；本人修改确认页面；没有正式对照实验。

可写的内容方向：描述观察和页面修改，说明这促使申请人关注反馈是否足够清楚；将“更好用”作为待评估问题。不能写成“通过实验显著提高转化率”或“提出新的人机交互理论”。

如果用户补充了真实评估：加入方法、样本和结果，仍保留评估范围。反思应与评估支持的结论一致。

## 不同交付模式

- 诊断：先指出最影响说服力的三项问题，引用用户短句定位；用户未限定只诊断时继续给修订后的正文。
- 提纲：每段写论点、证据、与下一段关系和待确认项，避免只列 motivation 等栏目名。
- 初稿：有材料即可推进，缺口与成稿分开；不要把工作占位符当定稿。
- 润色：保护已确认事实与范围，若发现根本逻辑问题先说明，不通过漂亮句子掩盖。
- 翻译：保持可信强度，统一术语与英美拼写；不照搬中文长句结构。
- 定向适配：保留事实底稿，重新检视目标、素材顺序、资源和结尾，维护一致性。
